# LLM とは何か — 中身とコスト構造

「LLM を呼び出す」「LLM API を使う」と言ったとき、**呼んでいる相手の中身** は何なのか。Big Tech が作り、SaaS 企業が借りるという階層がどうしてそうなっているのか。LLM の正体とコスト構造を一度地図にしておく。

## LLM の正体: 「次のトークンを予測する確率モデル」

**LLM = Large Language Model（大規模言語モデル）**。

最も素朴に言うと、**「次に来る単語を確率で予測する関数」** に過ぎない。

```
入力:  "日本の首都は"
↓ LLM が確率分布を計算
出力:  「東京」 → 92%、「大阪」 → 3%、「京都」 → 2%、その他 → 3%
↓ 一番確率の高いものを選ぶ（あるいはサンプリング）
回答:  "東京"
```

これを **トークン（≒ 単語）単位で 1 つずつ繰り返す** ことで、文章が生成される。

「**意味を理解している**」というより、「**膨大な文章パターンから次に来そうなものを統計的に予測している**」のが実態。それでも結果として要約・翻訳・コード生成・推論など多様なタスクをこなせる。

## 技術的な中身

| 要素 | 内容 |
|---|---|
| **アーキテクチャ** | 主に **Transformer**（2017 年に Google が "Attention Is All You Need" で発表） |
| **キー機構** | **Attention 機構**。「どの単語がどの単語と関係しているか」を重み付けで取り込む |
| **入力** | テキストを **トークン**（部分文字列）に分割、それぞれを **埋め込みベクトル**（数百〜数千次元の数値の並び）に変換 |
| **訓練方法** | 大量のテキストで「**次のトークンを当てる**」自己教師あり学習 |
| **パラメータ** | ニューラルネットの **重み**。数十億〜数兆個 |
| **出力** | 語彙全体に対する確率分布 |

### Transformer の超ざっくりイメージ

```
[ "日本" "の" "首都" "は" ]  ← トークン列
        │ 埋め込み（各トークン → 高次元ベクトル）
        ▼
[ ベクトル列 ]
        │ Attention 層（各ベクトル同士の関連度を計算）
        │ × 数十〜百層
        ▼
[ 文脈を取り込んだベクトル列 ]
        │ 最後の位置のベクトルから次のトークン確率を出す
        ▼
[ "東京": 0.92, "大阪": 0.03, ... ]
```

minilang の AST と同じく、「**入力を中間表現に変換 → 演算 → 出力**」の構造だが、中間表現がベクトル、演算が線形代数 + 非線形変換、というだけ。

## なぜ "Large" なのか

| 観点 | 規模 |
|---|---|
| パラメータ数 | 数十億（小型）〜 数千億 〜 1 兆超（最大） |
| 訓練データ | 数兆トークン（書籍数百万冊相当） |
| 訓練時間 | 数週間〜数ヶ月、数千〜数万枚の GPU を並列稼働 |
| モデルサイズ | ストレージ上で数十 GB〜数 TB |

「言語モデル」自体は 1990 年代からあった（n-gram モデル等）。**規模を桁違いに大きくしたら質的に違う能力が現れた**（emergent abilities：少数事例からの学習、推論連鎖、コード生成など）── これが 2020 年以降の「LLM ブーム」の正体。

## 訓練の流れ（3 段階）

```
[ 1. Pre-training ] ← 数兆トークンで「次の単語予測」を学習
        │
        ▼
[ 2. Fine-tuning ] ← 指示に従う形式に調整（SFT = Supervised Fine-Tuning）
        │
        ▼
[ 3. RLHF / RLAIF ] ← 人間（または別の AI）の好みを反映（強化学習）
        │
        ▼
[ デプロイ可能なモデル ]
```

| 段階 | 何をする | コストの主体 |
|---|---|---|
| **Pre-training** | 大量データで言語能力の土台を作る | **★ ここが最も巨大なコスト** |
| **Fine-tuning (SFT)** | 「ユーザーの指示に応える」形式を学ぶ | 比較的小さい（pre-training の 1/100 以下） |
| **RLHF / DPO** | 「良い応答 / 悪い応答」のフィードバックで調整 | 中規模（人手データ収集が高い） |

「LLM が高い」と言うとき、**ほぼ全部 pre-training の話**。

## コストの実態（前回の補足）

「数兆円規模」とざっくり書いたが、より正確には層別する:

| 規模 | コスト目安 | 例 |
|---|---|---|
| **個別モデル 1 つの pre-training（訓練ジョブ）** | **数億 〜 数百億円** | GPT-3: 約 6 億円 / GPT-4: 推定 70〜140 億円 / 最新世代: 数百億円 |
| **フロンティアラボ全体の年間 AI R&D 投資** | **数千億 〜 数兆円** | OpenAI / Anthropic / Google DeepMind / xAI の **総投資額** |
| **データセンター・GPU 設備への先行投資** | **兆円規模** | Microsoft / Google / AWS / Meta の AI インフラ投資 |

**モデル 1 つを訓練するだけ** なら数億〜数百億円。**フロンティアラボとして競争し続ける** なら継続的に数千億〜数兆円が必要、という構造。

### なぜそんなにコストがかかるのか

| 要素 | コスト要因 |
|---|---|
| **GPU** | 1 枚 数百万円の H100 / B200 を **数千〜数万枚**、数週間〜数ヶ月稼働 |
| **電力** | データセンター級。原発 1 基分という比喩も使われる |
| **データ** | 数兆トークンのテキスト収集・クリーニング・前処理 |
| **人材** | 機械学習研究者 + インフラエンジニア + データ工学者。1 人あたり年俸数千万〜数億円規模 |
| **試行錯誤** | 1 回の本訓練の前に、多数の小規模実験を回してハイパーパラメータ調整 |
| **失敗のリスク** | 訓練が途中で発散したら数億〜数十億円が消える |

## オープンソース / オープンウェイト LLM の世界

「pre-training は Big Tech だけ」ではない。中規模なら他のプレイヤーも参戦している:

| モデル | 規模 | 開発元 |
|---|---|---|
| **Llama 3 / 4** | 8B〜400B | Meta（オープンウェイト） |
| **Mistral** | 7B〜数百B | Mistral AI（フランス） |
| **Qwen** | 1.5B〜数百B | Alibaba |
| **DeepSeek** | 7B〜数百B | DeepSeek（中国） |
| **Gemma** | 2B〜27B | Google（オープンウェイト） |
| **Phi** | 3.8B〜14B | Microsoft（小型特化） |

これらでも訓練には **数十億〜数千億円規模** がかかる。個人で pre-training を作るのは現実的でないが、**Fine-tuning** や **LoRA** などのアダプタなら数万〜数百万円で可能。

## LLM の使い方の階層

「LLM を使う」と言ったとき、**どの層で関わるか** で必要なリソースが変わる:

| 層 | 何をする | 必要規模 | 主な担い手 |
|---|---|---|---|
| 1. **Pre-training** | foundation model を作る | 数億〜数百億円 + 数万枚 GPU | Big Tech / 一部の OSS 組織 |
| 2. **Fine-tuning** | 既存モデルを特定タスク向けに調整 | 数万〜数百万円 + GPU 数台 | 中規模企業 / 研究機関 |
| 3. **LoRA / アダプタ** | パラメータの一部だけ調整 | 数千〜数万円 + GPU 1 台 | 個人 / 中小企業 |
| 4. **プロンプト + ツール呼び出し**（AI エージェント層）| API で呼び出して業務に組み込む | API 利用料のみ | **★ 多くの SaaS 企業はここ** |
| 5. **API クライアントとして使う** | ChatGPT 等のサービスを使うだけ | 月額数千〜数万円 | エンドユーザー |

**LayerX（SD 記事の主役）は 4 番** の層で勝負している。LLM 本体は OpenAI / Anthropic / Google の API を借りる。

## LLM API を「借りる」とはどういうことか

実装的には、HTTP POST リクエストを送って JSON で結果を受け取るだけ:

```bash
curl https://api.anthropic.com/v1/messages \
  -H "x-api-key: $API_KEY" \
  -H "anthropic-version: 2023-06-01" \
  -H "content-type: application/json" \
  -d '{
    "model": "claude-opus-4-7",
    "max_tokens": 1024,
    "messages": [{"role": "user", "content": "日本の首都は?"}]
  }'
```

`api.anthropic.com` の向こう側で **数百億円かけて訓練したモデルが動いている**。利用者はその巨大計算を **トークン単位の従量課金** で借りている。

これは [process-and-protocol.md](process-and-protocol.md) の「プロセス × プロセス間通信」の応用:

- ローカルの **AI エージェント層プロセス**（LayerX が書いた Python / TypeScript）
- ↑↓ HTTP + JSON で通信
- リモートの **LLM 推論サーバ**（Anthropic のデータセンターで動く）

## まとめ

- LLM の正体は **「次のトークンを予測する確率モデル」**（中身は Transformer + Attention）
- "Large" の意味は **数十億〜数兆のパラメータ + 数兆トークンの訓練データ + 数千〜数万枚 GPU**
- **pre-training は 数億〜数百億円規模**、フロンティアラボの継続投資は **数千億〜数兆円**
- **モデルを作る**（Big Tech / OSS 大手）と、**API で借りて応用層を作る**（中堅 SaaS）が経済合理的に分離している
- **LayerX のような企業** は、**LLM の上に「業務をやらせるオーケストレーション層」を自社で実装** することで価値を出している

「LLM とは何か」を一度押さえると、AI エージェント周りの記事を読むときに **どの層の話か** が見えやすくなる。
