# ML と AI エージェントの位置関係

「ML 中心時代から AI エージェント時代へ」と聞いたとき、両者が **対立しているのか / 別物なのか / 同じものなのか** が分かりにくい。実態は **ML が土台、AI エージェントがその応用形** という階層関係。この note はその地図。

## 階層関係

```
[ AI（大きな分野） ]
   │
   ├── ルールベース AI（古典、手書きルール）
   │
   └── 機械学習 ML（データから学ぶ）
          │
          ├── 古典的 ML（決定木、SVM、線形回帰、ランダムフォレスト など）
          │
          └── 深層学習 DL（ニューラルネット）
                 │
                 ├── 画像認識（CNN）、音声認識（RNN）など
                 │
                 └── ★ LLM（大規模言語モデル）
                       │
                       └── ★ AI エージェント
                             （LLM を中核にツール呼び出し・記憶・推論を組み合わせたシステム）
```

LLM は **DL の中の一種**、AI エージェントは **LLM を中で使っているシステム**。AI エージェントは ML の置き換えではなく、ML の延長線上の応用形。

## 各用語の定義

| 用語 | 何 | 例 |
|---|---|---|
| **AI** | 「知的な処理をする」分野の総称（広い）| 画像認識、翻訳、ゲーム AI、推薦システム |
| **機械学習 (ML)** | **データから学習する**アルゴリズム / モデル全般 | スパムフィルタ、レコメンド、需要予測 |
| **深層学習 (DL)** | ML のうち、**ニューラルネット**を使うもの | 画像認識（CNN）、音声認識（RNN）、自然言語処理（Transformer）|
| **LLM** | DL のうち、**大量テキストで訓練した言語モデル** | GPT-4、Claude、Gemini |
| **AI エージェント** | LLM を中核に、**ツール呼び出し・記憶・自律判断** を組み合わせたシステム | バクラクの申請レビュー、Claude Code、ChatGPT の Code Interpreter |

「AI エージェント」は **LLM の単独利用ではなく、システムとして組み立てたもの**。

## ML と AI エージェントの「開発の質」の違い

SD 連載で「ML 中心時代から AI エージェント時代へ」と書かれているのは、**開発の仕事の質が変わった** という意味:

| | ML 中心時代 | AI エージェント時代 |
|---|---|---|
| **作るもの** | 1 つの予測モデル | 複数の LLM 呼び出し + ツール + 状態を組み合わせたシステム |
| **入力 → 出力** | 単純（画像 → ラベル、テキスト → 分類）| マルチステップ（指示 → 判断 → ツール呼び出し → 結果）|
| **モデル本体** | **自社で訓練することが多い** | **外部の LLM API を借りる**（OpenAI / Anthropic 等） |
| **評価対象** | モデルの予測精度 | **業務タスクの達成可否** |
| **改善サイクル** | 遅い（モデル再訓練が必要、数日〜数週間）| 速い（プロンプト変更だけで挙動が変わる、即時） |
| **主役の職種** | データサイエンティスト / ML エンジニア | ソフトウェアエンジニア + プロンプト設計 + ML エンジニア |

「ML エンジニアほど見落としやすい変化」と SD 記事にあったのは、**ML 時代の感覚（オフライン評価を詰めきってからリリース）が AI エージェントには合わない** という話。AI エージェントはプロンプト変更で挙動が変わるので、**オンラインで学ぶ** ほうが速い。

## AI エージェントの中身

「LLM を使って業務処理する」とは具体的に何か。LLM の **単独呼び出し** と **エージェント** の違いがポイント:

| | ただの LLM 呼び出し | AI エージェント |
|---|---|---|
| 構造 | 入力 → LLM → 出力（1 回）| ループ: LLM の判断で次のツールを選ぶ |
| 例 | ChatGPT に質問して答えをもらう | AI が「まず検索 → 次に要約 → 次に判定」と **自分で計画して実行** |
| 制御フロー | ユーザーが決める | **LLM が決める**（ある程度） |
| ツール呼び出し | なし or 1 つ | 複数のツールを **自律的に選んで** 呼ぶ |
| 状態管理 | ステートレス | 進行状況・記憶を持つ |

「**自律的にループする**」がエージェントの肝。

## バクラクでの具体例

LayerX の業務 SaaS「バクラク」に組み込まれた **申請レビュー AI エージェント** の内部構造:

```
[ ユーザー: 「この経費申請を承認していい?」]
        │
        ▼
[ AI エージェント層（LayerX が自社実装）]
   │
   ├── 1. LLM API（Claude / GPT）を呼んで申請内容を理解
   │
   ├── 2. ツール呼び出し: 過去の類似申請を検索
   │
   ├── 3. ツール呼び出し: 帳票から項目抽出
   │
   ├── 4. LLM API をもう一度呼んで承認 / 却下を判断
   │
   └── 5. フィードバックメッセージを生成
        │
        ▼
[ ユーザー: 「承認です。理由は...」]
```

各ステップで:

- **LLM 本体**（モデル）= 外部の API（OpenAI / Anthropic 等）
- **ツール**（過去申請検索、項目抽出など）= LayerX が用意したシステム
- **判断ロジックの繋ぎ方** = LayerX が自社実装した AI エージェント層

つまり「**LLM ＋ ツール ＋ 業務ロジック**」を組み合わせて、業務を自律的に進めるシステムが「AI エージェント」。

## 「自律的に進める」がエージェントのビジョン

SD 記事（LayerX）に書かれているビジョン: **「Agent が自律的に業務を進め、必要な確認のみを人が行う」「気づいたら仕事が終わっている」状態**。

これは:

- 人が指示する範囲を最小に
- AI が中間判断を自分でする（どのツールを呼ぶか、何を確認するか）
- 人は **最終確認や例外対応** に集中

という働き方の変化を狙っている。

## 4 切り（[learning-by-slicing.md](learning-by-slicing.md)）で見ると

| 切り方 | ML / LLM / AI エージェントでの実体 |
|---|---|
| **A. プロトコル** | LLM API の仕様（OpenAI / Anthropic のスキーマ）、Function Calling 仕様、ACP（エディタ ↔ エージェント） |
| **B. パケット** | API リクエスト / レスポンスの JSON、エージェントの Trace ログ |
| **C. 設定** | プロンプト、モデル選択、ツール定義、temperature、エージェントのループ条件 |
| **D. 実装** | LLM 本体（外部）+ AI エージェント層のコード（自社） |

LayerX のような SaaS 企業が **競争している層は D の「AI エージェント層」**。LLM 本体は A の API 仕様越しに借りる。

## 「自社で実装」する範囲の整理

| 層 | 誰が作るか |
|---|---|
| LLM 本体（Claude / GPT-4 / Gemini） | **Anthropic / OpenAI / Google**（外部）|
| **AI エージェントのオーケストレーション層** | **自社で実装**（LayerX が書く） |
| **業務ロジック / プロンプト / 評価 / 監視** | **自社で実装** |
| 業務 SaaS の UI / DB / 既存機能 | **自社で実装**（バクラクの本体）|

[llm-fundamentals.md](llm-fundamentals.md) で書いた **「LLM は道具箱、AI エージェント層がその利用者」** の構造と整合します。

## まとめ

- **AI > ML > DL > LLM** という階層、**AI エージェントは LLM を中核にしたシステム**
- ML と AI エージェントは **対立ではなく、ML が土台で AI エージェントがその応用形**
- 開発の質が変わった: **モデル訓練中心** → **LLM API + ツール + プロンプトの組み合わせ中心**
- LayerX のような業務 SaaS 企業は **AI エージェント層を自社で実装**、LLM 本体は API で借りる
- 「ただの LLM 呼び出し」と「AI エージェント」の違いは **自律的なループの有無**
